## 2. 术语与不变量

### 2.1 术语

| 术语 | 含义 |
|------|------|
| **Signal（信号）** | 一条检测结论，结构为 `id / category / score / evidence / state / layer / weightHint` |
| **Provider** | 信号来源接口 `RiskSignalProvider`，返回 `[RiskSignal]` 和可选 `ServerSignals` |
| **Detector** | 越狱/反篡改检测器接口 `Detector.detect() throws -> DetectorResult`，由 `DetectorRegistry` 编排 |
| **Verdict（判决）** | `LocalAssessment`：`score / internalLevel / internalAction / confidence / primaryReasons / signals` |
| **Report（报告）** | `CPRiskReport`：面向调用方的只读视图 + 内部可序列化 `Payload` |
| **Envelope（信封）** | `ReportEnvelope`：payload + 会话 + 时间 + nonce + HMAC 签名 (+ App Attest) |
| **TrustLevel** | `hardware` / `derived` / `degraded`，表示密钥材料可信度 |
| **fail-closed** | 任何内部状态异常时，默认输出“最高风险 + block”，而不是放行 |

### 2.2 全局不变量（实现必须始终满足）

| # | 不变量 | 校验点 |
|---|--------|--------|
| I1 | `start()` 之后 provider 注册表**已封存**，运行期不可再注册 | `RiskSignalProviderRegistry.shared.seal()` |
| I2 | 签名输入只使用**规范化 JSON**（sortedKeys），不使用原始字节顺序 | `canonicalJSONString(from:)` |
| I3 | 任何未进入签名域的字段都视为可伪造，不得参与服务端信任决策 | v3 签名域设计 |
| I4 | 信封构建失败时**绝不降级为无签名明文上报** | `requireArmor` / `requireAttestation` |
| I5 | 同一 `nonce` 在 300s 窗口内只允许签发一次 | `ClientNonceWindow` |
| I6 | 引擎内部状态机被污染时输出 `engine_region_poison` + score=100 + block | `failClosedVerdict` |
| I7 | 远程配置只允许版本前进；同版本内容不同则拒绝 | `applyRemoteConfigIfAccepted` |
| I8 | Release 构建拒绝 `http://` 远程配置端点 | `configureRemoteConfigProvider` |
| I9 | Payload 落盘必须加密；信封 payload 本身是明文 JSON + HMAC | `CPRiskStore` vs `ReportEnvelope` |
| I10 | kill switch 生效时输出 allow，但必须写审计日志 | `kill_switch_activated` |

> ⚠️ I9 容易被误解：`buildSecureReportEnvelope()` 生成的 `payload` 字段是**明文 JSON**，
> 其机密性由 TLS + 字段混淆（`payloadFieldMapping`）提供，完整性由 HMAC 提供。
> AES-GCM 的 `securePayload()` 只用于**本地落盘**，不是上报链路的一部分。

## 4. 阶段 S1：初始化 `start()`

**实现**：`Core/CPRiskKitLifecycle.swift:24` `startImpl(config:)`

### 4.1 前置条件

| 条件 | 要求 |
|------|------|
| 调用时机 | App 启动早期，早于首次 `evaluate()` |
| 线程 | 任意线程（内部会把主线程相关操作派发到 main） |
| 重复调用 | 允许；每次都会重新走一遍初始化（会重建 sessionId） |
| 测试环境 | 检测到 XCTest 时使用 `CPRiskConfig()` 且禁用远程配置 |

### 4.2 步骤规格

| # | 步骤 | 代码 | 说明 |
|---|------|------|------|
| 1 | 稳定性会话 | `ProtectionStabilityStore.beginSession(...)` | 可能触发远程配置回滚、进入本地安全档或本地 kill switch |
| 2 | 配置复制 + 安全档 | `duplicatingRiskConfig(_:forceAppStoreSafe:)` | 本地安全档激活时强制 `antiDebugRuntimeMode = .appStoreSafe` |
| 3 | 反调试配置 | `applyAntiDebugRuntimeConfigToCore` | 写入 C 层运行时模式 |
| 4 | 反调试启动 | `cprisk_deny_attach()`、`cprisk_register_exception_handler()`、`cprisk_start_anti_debug_watchdog()` | AppStoreSafe 下**全部跳过** |
| 5 | 看门狗心跳 | `scheduleMainThreadWatchdogHeartbeat()` | 1s 间隔，主线程存活标记 |
| 6 | Armor 运行时 | `ensureArmorRuntimeStarted(trigger: "start")` | 状态写入 `armorRuntimeSnapshot` |
| 7 | 擦除 Mach-O 头 | `cprisk_erase_macho_header()` | 仅当 `!appStoreSafe && armor.status == .active`；**不可逆** |
| 8 | 反 dump | `cprisk_start_anti_dump_probe(5)` | AppStoreSafe 下跳过 |
| 9 | 运行时健康快照 | `recordRuntimeHealth(...)` | armor 状态、watchdog/anti-dump 返回码 |
| 10 | dyld 监控 | `DyldImageMonitor.shared.start()` | |
| 11 | 构建配置 | `BuildConfig.configureForRelease()` | |
| 12 | 会话 ID | `currentSessionId = UUID().uuidString` | 参与 graph 绑定与报告 |
| 13 | Provider 注册 | `registerProviders(for:)` → `BuiltInProviderBootstrap.apply` | |
| 14 | 封存 | `RiskSignalProviderRegistry.shared.seal()`、`ConditionExpression.sealCustomEvaluators()` | 不可逆 |
| 15 | 图反馈观察者 | `installGraphFeedbackReEvaluateObserver()` | 图反馈到达时自动重评（可关闭） |
| 16 | 行为采集 | `touchCapture.start()`、`motionSampler.start()`、`PhysicalSensorProbe.prewarm()` | 仅 UIKit 平台 |
| 17 | 完成标记 | `markStartupCompleted(remoteConfigVersion:)` | |

### 4.3 输出状态

| 状态 | 类型 | 生命周期 |
|------|------|----------|
| `currentSessionId` | `String?` | 到 `stop()` / `unbindAccount()` |
| `armorRuntimeSnapshot` | `ArmorRuntimeSnapshot` | 到 `resetArmorRuntime()` |
| `lastAppliedEffectiveAntiDebugMode` | 枚举 | 到下一次配置变更 |
| provider 注册表 | sealed | 进程级 |
| watchdog 心跳 Timer | `Timer?` | 到 `stop()` |

### 4.4 失败模式

| 失败点 | 行为 | 后续影响 |
|--------|------|----------|
| watchdog 启动失败 | 日志 `anti_debug_*.start failed rc=...`，取消心跳 | 反调试能力降级（可被 evaluate 信号观测） |
| armor 启动失败 | `armorSnapshot.status != .active` | **信封默认构建会 throw**（除非显式 `requireArmor: false`） |
| anti-dump 失败 | 日志 | 无阻断 |
| AppStoreSafe 模式 | 跳过 attach 拒绝/异常处理/看门狗/反 dump/擦头 | 合规优先，评估链路仍完整 |

### 4.5 约束

- `cprisk_erase_macho_header()` 执行后 `dladdr`、dyld 内省、符号解析、崩溃符号化均**永久失效**，且无法恢复。只在 armor 成功时执行。
- XCTest 环境下会重置稳定性状态并禁用远程配置，保证测试可重复。

### 5.3 上下文采集规格

| 字段 | 来源 | 备注 |
|------|------|------|
| `device` | `DeviceFingerprint.current()` | 硬件标识、机型、GPU、kernel build 等 |
| `deviceID` | `KeychainDeviceID.shared.getOrCreate()` | Keychain 持久化；清 Keychain 会改变 |
| `network` | `NetworkSignals.current()` | 含电池状态（`batteryLevel` / `batteryState`） |
| `behavior.touch` | `TouchCapture.snapshotDetailAndReset()` | **调用后清零**，统计窗口由调用方频率决定 |
| `behavior.motion` | `MotionSampler.snapshotDetailAndReset()` | 同上 |
| `behavior.touchMotionCorrelation` | `BehaviorCoupling.touchMotionCorrelation(...)` | 触摸-运动相关性 |

### 5.4 信号汇聚顺序与来源

```
extraSignals =
    registry.signals(snapshot)                 // 所有内置 + 自定义 provider
  + armorRuntimeSignal                         // armor 启动失败/异常
  + integrityRecheckPoisonedSignal             // cprisk_is_integrity_poisoned() != 0
  + capabilityProbe.score.toSignal()            // 能力探针异常
  + localDeviceClusterSignal                    // 本地同机群检测
  + challengeMismatchSignals                    // 挑战结果不一致
  + remoteConfigStaleSignal                     // 远程配置陈旧
  + signalSuppressionDetected                   // 高危信号消失
  + ScenarioPolicySignalBridge.deriveSignals    // 场景派生
```

### 5.5 信号抑制检测规则

| 条件 | 输出 |
|------|------|
| 上一轮高危集合中消失的信号数 ≥ 2 | `signal_suppression_detected`，score 80，`.tampered`，weightHint 80 |
| 上一轮有高危信号且本轮一个都没有 | 同上 |

高危信号集合见 `CloudPhoneRiskKit.swift:82` `highRiskSignalIds`（Frida、hook、RWX、代码签名、armor 篡改、内核 hook、dyld 注入等）。

**语义**：攻击者通过 hook 只屏蔽部分检测时，信号会“凭空消失”，这本身是强攻击证据。

### 5.6 报告对象构建

| 字段 | 值 |
|------|-----|
| `reportID` | `UUID().uuidString` |
| `deviceID` | context.deviceID |
| `score` | `LocalAssessment.score` |
| `isHighRisk` | `LocalAssessment.isHighRisk`（等价于 `internalLevel >= high`，**不等价于 block**） |
| `tampered` | payload.tamperedCount > 0 |
| `signals` | 全部参与评分与展示的信号 |
| `detectedMethods` | 越狱方法 + 反篡改方法前缀合并 |

**反篡改增强越狱**：若存在 `category ∈ {anti_tamper, integrity}` 且 `state == .tampered` 的信号，而越狱检测未命中，则：

```
boostedConfidence = max(jailbreak.confidence, sum(tamperedScores) * 0.5)
isJailbroken      = boostedConfidence >= 50
detectedMethods  += "anti_tamper:<signal_id>" × n
```

## 6. 阶段 S3：本地判决算法规格

**实现**：`LocalAssessment/RiskDetectionEngine.swift`

### 6.1 引擎策略 `EnginePolicy`

| 字段 | 来源 | 说明 |
|------|------|------|
| `name` / `version` | `remote_<version>` 或 `local_sdk3` | |
| `killSwitchEnabled` | 远程 `securityHardening.killSwitchEnabled` **或** 本地稳定性 kill switch | 见 6.6 |
| `enableNetworkSignals` / `enableBehaviorDetection` | 运行时配置 | |
| `forceActionOnJailbreak` | 固定 `.block` | |
| `signalWeightOverrides` | 服务端策略 | 按 signal id 覆盖权重 |
| `mutationStrategy` | 服务端 `mutation` | 阈值/分数抖动、检查顺序打乱 |
| `blindChallengePolicy` | 服务端 `blindChallenge` | 盲挑战加分 |
| `serverBlocklist` / `blocklistAction` | 服务端 | 命中即 block |
| `scenarioPolicies` | 见 6.2 | 每个 `RiskScenario` 一份 |

### 6.2 场景阈值推导

对每个场景：

```
highThreshold     = clamp(server.challenge ?? runtimeConfig.threshold, 1, 100)
mediumThreshold   = clamp(server.monitor ?? remote.mediumThreshold ?? base.medium, 0, highThreshold - 1)
criticalThreshold = clamp(max(highThreshold + 1,
                              server.block ?? max(base.critical, highThreshold + 20)), _, 100)
```

默认基线（`ScenarioPolicy` 初始化值）：`medium = 30`，`high = 55`，`critical = 80`。

### 6.3 信号状态语义

| 状态 | 计分方式 |
|------|----------|
| 无 `state`（legacy 数值信号） | `score × categoryWeight`（可抖动） |
| `.hard(detected: true)` | 按 signal id 去重取**最大权重**，聚合为 `hardScore` |
| `.hard(detected: false)` | 不计分 |
| `.soft(confidence)` | 仅当 `confidence > softGate`（默认 0.3）时计 `weight × confidence × 0.3` |
| `.tampered` | 计入 `tamperedCount`，并加 `max(60, weight)` 到 soft 分量 |
| `.serverRequired` / `.unavailable` | 不计分 |

### 6.4 计分公式

```
// 多硬信号按权重降序折扣聚合，避免多个同源信号简单相加导致分数爆炸：
//   total = w1 + w2×0.45 + w3×0.30 + w4×0.20 + w5..×0.15，上限 100
hardScore = aggregateHardScore(distinctMaxWeights)
tamperedMultiplier = 1.0 + 0.5 × tamperedCount
v3Component = (hardScore + softScore) × tamperedMultiplier
legacyScore = Σ(score × categoryWeight)
baseTotal   = clamp(legacyScore + v3Component, 0, 100)

// 可选：白盒 PRF 域求值产生 ±1 的确定性扰动（抗静态复现）
total = clamp(baseTotal + prfDelta, 0, 100)

// 后续调整
finalScore = clamp(total + comboBonus + blindChallengeBonus + challengeOffset, 0, 100)
```

**权重优先级**（`signalWeight`）：

```
max(weightHint, criticalSignalMinWeights[id])          // weightHint 优先
→ max(override, minWeight)                              // 服务端覆盖
→ max(defaultV3SignalWeights[id], minWeight)            // 内置默认
→ max(signal.score, minWeight)                          // 最终回退
```

`criticalSignalMinWeights` 为关键信号设定不可下调的权重下限（如 `rop_chain_detected: 90`、`signingChainConsensus: 60`、`vphone_hardware: 50`），防止伪造 provider 用低 `weightHint` 绕过。

### 6.5 组合规则 / 强制规则 / 保底

| 机制 | 作用 | 示例 |
|------|------|------|
| `ComboRule` | 多信号同时在场时加 `bonusScore`，可带 `forceAction` | CR-001 越狱+调试+内核异常 → +30 + block |
| N-of-M 带权规则 | 加权阈值 + 最少命中数 + 必需信号 | `impossible_states_cloudphone`：5 选 4，权重阈值 70，`usb_audio_routed` 必需 |
| 强制动作 | 直接抬升分数到该动作的最低分并锁定动作 | 越狱 → block；blocklist 命中 → block |
| 证书固定保底 | `payment/register/login/accountChange/sensitiveAction` 场景下按 pinning 信号等级抬分 | soft→medium，hard→high，tampered→critical |
| 分数档位保底 | `action_for_level(score)` 不弱于初步动作 | 防止树路径放行已超阈值的情况 |

动作对应的最低分（`minScore`）：

| 动作 | 最低分 |
|------|--------|
| `allow` | 0（**不抬分**） |
| `challenge` | `mediumThreshold` |
| `stepUpAuth` | `highThreshold` |
| `block` | `criticalThreshold` |

### 6.6 等级与动作映射

| 内部等级 | 分数区间（默认阈值） | 默认动作 | 公开等级 | 公开动作 |
|----------|---------------------|----------|----------|----------|
| `low` | `[0, 30)` | `allow` | low | allow |
| `medium` | `[30, 55)` | `allow` | medium | allow |
| `high` | `[55, 80)` | `challenge` | high | challenge |
| `critical` | `[80, 100]` | `block` | high | block |

> 注意：`medium` 默认映射到 `allow`，仅用于监控与灰度；需要“中风险挑战”时须由服务端策略显式改写 `actionMapping`。

### 6.7 短路路径（按执行顺序）

| 顺序 | 路径 | 触发条件 | 输出 |
|------|------|----------|------|
| 1 | kill switch | `killSwitchEnabled && !localOverride` | score 0 / low / allow / confidence 1.0 / `kill_switch_active` |
| 2 | 区域污染 | 状态机解码异常 / budget 超限 | `engine_region_poison`，score 100 / critical / block |
| 3 | preflight | 前置规则命中 | 直接返回 |
| 4 | 压缩摘要规则 | 位向量匹配 `CompressedVerdictRule` | 取最严格动作，confidence 1.0；随后与完整计分结果对账（取较高分/较严动作） |
| 5 | 完整路径 | 以上均未命中 | 计分 → 组合 → 强制 → 树提交 → 对账 |

### 6.8 置信度

```
confidence = 0.3
           + min(0.05 × signalCount, 0.3)
           + min(0.1 × count(score >= 10), 0.2)
           + 0.2  if jailbreak detected
           + 0.1  if actionCount >= 10
confidence = clamp(confidence, 0, 1)
```

非有限值或负值统一回退到 0.5。

### 6.9 主要原因

按 `max(score, weightHint)` 倒序取前 5，格式 `category_signalId`（`id == category` 时只取 category）。写入 `primaryReasons`，并随报告上报。

## 7. 阶段 S4：安全信封 `buildSecureReportEnvelope()`

**实现**：`Core/CPRiskKitReporting.swift:14`、`Risk/ReportEnvelope.swift`

### 7.1 输入

| 参数 | 必填 | 说明 |
|------|------|------|
| `report` | ✅ | `evaluate()` 产物 |
| `sessionToken` | ✅ | **服务端下发**的短期会话令牌 |
| `signingKey` | ✅ | 与服务端共享的签名基密钥（HMAC IKM） |
| `keyId` | 默认 `k1` | 存在密钥轮换策略时替换为轮换后的 keyId |
| `attestationKeyId` | 可选 | 走 `WithAttestation` 路径时填入 |
| `requireArmor` | 默认 `true` | 是否强制要求 Armor 派生签名 |

### 7.2 构建步骤

| # | 步骤 | 规则 |
|---|------|------|
| 1 | 读取远程硬化配置 | `securityHardening` |
| 2 | 字段映射校验 | 见 7.3 |
| 3 | 生成上传 payload | `report.secureUploadPayloadData(includeChallengeBinding:)`；未开启挑战绑定时剔除 `cb` |
| 4 | 解析 keyId | 有轮换策略则 `TrustChainManager.currentKeyId(baseKeyId:)` |
| 5 | 评估 TrustLevel | `hardware` / `derived` / `degraded` |
| 6 | 选择签名材料 | 见 7.4 矩阵 |
| 7 | 创建信封 | `ReportEnvelope.create(...)` |

### 7.3 字段映射（payloadFieldMapping）

| 远程配置状态 | 行为 |
|--------------|------|
| `enforcePayloadFieldMapping == true` 且映射缺失 | **throw** `payloadFieldMappingRequired` |
| 映射已过期且强制 | **throw** `payloadFieldMappingExpired(version:)` |
| 映射已过期且非强制 | 忽略映射，按原字段签名 |
| 映射有效 | `PayloadFieldObfuscator.obfuscate(jsonData:mapping:)` 重命名字段；`fieldMappingVersion` 进入签名域 |

### 7.4 签名材料选择矩阵

| Armor 状态 | 完整性 | `requireArmor` | 签名实现 | `sigVer` | `bindingMode` |
|------------|--------|----------------|----------|----------|---------------|
| `.active` | 未污染 | 任意 | CRiskCore 派生密钥 + 请求绑定摘要 | `v2a`（DEBUG 可为 `v1`） | `armor_request_binding_sha256_v1` |
| `.active` | 已污染 | `true` | — | — | **throw** `armorRuntimeUnavailable(material_poisoned)` |
| `.active` | 已污染 | `false` | 普通 HMAC | `v2d` | `plain_hmac_fallback_v1` |
| 非 `.active` | — | `true` | — | — | **throw** `armorRuntimeUnavailable(reason:)` |
| 非 `.active` | — | `false` | 普通 HMAC | `v2d` | `plain_hmac_fallback_v1` |

Armor 派生签名调用：

```c
cprisk_sign_with_derived_key_and_request_binding_digest(
    keyPtr, keyLen,
    inputPtr, inputLen,
    SHA256(signatureInput),   // request binding digest
    outHexBuffer
)
```

> 该路径显式设置 `allowLegacySignatureVersions: true`，属于**过渡期 legacy 签发**。
> 服务端必须拒绝 legacy 版本（`v1/v2/v2a/v2d/v2h`），直到上报链路整体切换到 v3。

### 7.5 nonce / 时间戳

| 字段 | 规则 |
|------|------|
| `nonce` | `UUID().uuidString`（v4，122 bit 熵） |
| `ts` | Unix **毫秒**；创建时只校验下界（≥ 2020-01-01） |
| 客户端去重 | `ClientNonceWindow`（默认 300s 窗口）；重复 → `replayDetected` |
| 服务端有效期 | `nonceExpirationMillis` 默认 300_000 |
| 允许时钟漂移 | `timeDriftToleranceMillis` 默认 ±300_000 |

### 7.6 签名域（必须逐字节一致）

**v3（默认，推荐）**：

```
v3|{nonce}|{ts}|{sessionToken}|{reportId}|{keyId}|{fieldMappingVersion}|{attestationKeyId}|{trustLevel}|{sha256Hex(attestationAssertion)}|{sha256Hex(reAttestationAssertion)}|{canonicalPayload}
```

**v2 / v2a / v2d / v2h**：

```
{sigVer}|{nonce}|{ts}|{sessionToken}|{reportId}|{keyId}|{fieldMappingVersion}|{attestationKeyId}|{canonicalPayload}
```

规则：

- 空字段以空串参与拼接，分隔符为 `|`。
- `canonicalPayload` = payload 经 `JSONSerialization` 解析后以 `.sortedKeys` 重新序列化的字符串。
- `canonicalPayload` 内含 `cd`（压缩摘要）与 `mv`（映射版本），因此压缩摘要间接被签名覆盖。
- v3 额外绑定 `trustLevel` 与两个 assertion 的 SHA-256，防止持密钥者替换自报字段。
- `v2h` 使用 HKDF 每请求派生密钥：`HKDF(IKM=signingKey, salt="{nonce}|{ts}", info="cprisk.report.hmac.v2h" + BE32(emuFlags))`。

### 7.7 信封 JSON 编码

内部字段名极简，用于节省体积：

| 语义 | JSON key |
|------|----------|
| nonce | `n` |
| ts | `t` |
| sessionToken | `st` |
| payload（base64） | `p` |
| reportId | `ri` |
| sigVer | `sv` |
| keyId | `ki` |
| fieldMappingVersion | `fm` |
| signature | `sg` |
| attestationKeyId | `ak` |
| attestationAssertion | `aa` |
| trustLevel | `tl` |
| reAttestationAssertion | `ra` |
| bindingMode | `bm` |
| bindingDigest | `bd` |
| requireHardwareAttestation | `rh` |

### 7.8 App Attest 路径

**实现**：`Core/CPRiskKitReporting.swift:401`、`Risk/AppAttestSigner.swift`

| 条件 | 行为 |
|------|------|
| 设备不支持 App Attest | `requireAttestation == true` → throw `hardwareTrustUnsupported`；否则构建无证明信封并置 `trustLevel = degraded` |
| 支持且成功 | 取 keyId → 生成 assertion（对 canonical payload 的 SHA-256）→ 附加 |
| 需要 re-attestation | 对 `policy.reAttestationChallenge` 额外生成 assertion；失败则降级 trustLevel |
| 不支持 / 失败且非强制 | 降级信封 + `degraded` |

关键约束：

- App Attest key 必须先在服务端完成 **enrollment**，否则 assertion 无法被验证。enrollment 通过 `CollectorClient.configureAppAttestEnrollment()` 注入。
- 挑战字节必须 ≥ 32 字节，且由服务端签发、单次使用。
- v3 要求 **所有证明材料在签名之前就已存在**；`withAttestation()` 对 v3 信封是 no-op（防止签名后被替换）。

## 8. 阶段 S5：传输通道

SDK 提供三种等价通道，调用方任选其一。

### 8.1 通道 A：调用方自建 HTTP

```swift
let envelope = try CPRiskKit.shared.buildSecureReportEnvelope(
    report: report, sessionToken: token, signingKey: key, keyId: "k1"

let body = try envelope.toGrpcRequestBytes(
    context: GrpcReportContext(appId: appId, deviceId: report.deviceID, scene: scene)

// POST body，Content-Type: application/json，Authorization: Bearer <token>
```

### 8.2 通道 B：信封 JSON 直传

```swift
let json = try envelope.toJSONString(prettyPrinted: false)  // { n, t, st, p, ri, sv, ki, sg, ... }
```

用于服务端按 `ReportEnvelope` 结构直接解析的场景（非 contract v1）。

### 8.3 通道 C：CollectorClient（推荐用于生产）

**实现**：`Risk/CollectorClient.swift`

| 项 | 规格 |
|----|------|
| 传输 | HTTPS only（非 https 直接 `invalidConfiguration`） |
| 鉴权 | `Authorization: Bearer <token>`，token 由服务端绑定 tenant/app/device/session |
| TLS | 默认会话启用证书 pinning，**`allowsSystemCA: false`**；无 pin 时不回退系统 CA |
| 超时 | 默认 10s（请求与资源同值） |
| Content-Type | `application/json` |
| 序列号化 | `AppAttestSigner.uploadGate` 串行化“取挑战 → 签名 → 提交”整段事务 |

**端点序列**：

| # | 端点 | 请求体 | 响应 | 说明 |
|---|------|--------|------|------|
| 1 | `POST /attestation/challenge` | `{"purpose": "enrollment"}` 或 `{"purpose": "assertion"}` | `{"challenge_id": "...", "challenge": base64}` | `challenge` 解码后必须 ≥ 32 字节 |
| 2 | `POST /attestation/enroll` | `{"key_id","attestation"(base64),"challenge_id"}` | 2xx | Apple attestation 链验证通过才算成功 |
| 3 | `POST /reports` | contract v1 JSON（见 8.4） | `{"evidence_id","report_id","idempotent_replay"?}` | 信封在此构建并签名 |

**提交顺序（不可调换）**：

1. 取 `assertion` 用途挑战
2. 生成 canonical payload
3. 生成 App Attest assertion（v3：assertion 必须在此刻已有）
4. `ReportEnvelope.create(..., attestationAssertion:, trustLevel: .hardware, config: v3 + requireHardwareAttestation)`
5. `POST /reports`

### 8.4 线上契约 `report-upload.schema.json` v1

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `kind` | string | ✅ | 固定 `"sdk_report"` |
| `contract_version` | int | ✅ | 固定 `1` |
| `app_id` | string | ✅ | 业务方 App 标识 |
| `sdk_version` | string | ✅ | 例 `9.0.0` |
| `report_id` | string | ✅ | 与 payload `ri` 一致 |
| `ts` | int64 | ✅ | Unix 毫秒，schema 约束 `[946684800000, 4102444800000)` |
| `nonce` | string | ✅ | 32+ 位随机串 |
| `session_token` | string | ✅ | 服务端下发 |
| `sig_ver` | string | ✅ | `v3` 推荐；`v1/v2/v2a/v2d/v2h` 为 legacy |
| `key_id` | string | ✅ | 用于密钥轮换 |
| `device_id` | string | ✅ | 必须与 payload 内 `di` 一致 |
| `scene` | string | ✅ | 必须与 payload 内 `st` 一致 |
| `payload_json` | string(base64) | ✅ | **canonical payload 的 UTF-8 字节**，服务端必须保留原始字节验签 |
| `signature` | string | ✅ | hex HMAC |
| `payload_sha256` | string(base64) | ✅ | 见下 |
| `field_mapping_version` | string | 可选 | 参与签名 |
| `trust_level` | enum | 可选 | `hardware` / `derived` / `degraded` |
| `attestation_key_id` | string | 可选 | |
| `attestation_assertion` | string(base64) | 可选 | |
| `re_attestation_assertion` | string(base64) | 可选 | |
| `binding_mode` | string | 可选 | 观测用 |
| `binding_digest` | string | 可选 | 观测用 |
| `output_path_integrity` | object | 可选 | 输出链路一致性证据 |

`payload_sha256` 计算：

```
SHA256( "{len(nonce)}:{nonce}|{ts}|{len(reportId)}:{reportId}|" ++ payloadBytes )
```

长度前缀用于防止字段内包含 `|` 时的拼接歧义。

**注意**：schema 为 `additionalProperties: false`，且 **`require_hardware_attestation` 不在线上字段中**——是否强制硬件证明只由服务端策略决定。

### 8.5 重试与幂等

| 场景 | 规则 |
|------|------|
| 网络结果不确定（超时/断连） | **必须用同一个信封重试**，不得重新 `create()`（nonce 已注册，重建会得到新 nonce，破坏服务端单次挑战语义） |
| 服务端明确拒绝（4xx） | 不重试；按错误码处理 |
| 5xx | 指数退避重试，仍用同一信封 |
| 服务端返回 `idempotent_replay: true` | 视为成功，说明此前已入库 |
| 挑战已消费 | 不得重新获取挑战绕过，必须等待服务端确认/过期 |

## 9. 阶段 S6：服务端验签与决策

### 9.1 验签顺序（必须严格按序）

| # | 校验 | 失败处理 |
|---|------|----------|
| 1 | `ts` 在允许窗口内（默认 ±300s） | 拒绝 `timestamp_out_of_range` |
| 2 | `nonce` 首次出现（按 session 维度） | 拒绝 `replay_detected` |
| 3 | `session_token` 有效且未过期 | 拒绝 401 |
| 4 | `payload_json` 是合法 JSON，**保留原始字节，不重新编码** | 拒绝 `invalid_payload` |
| 5 | 重算 `payload_sha256` 并比对 | 拒绝 `payload_binding_mismatch` |
| 6 | 校验 `signature`（按 `sig_ver` 选择签名域与密钥） | 拒绝 `signature_mismatch` |
| 7 | 顶层 `device_id` / `scene` 与 payload 内 `di` / `st` 一致 | 拒绝 `field_mismatch` |
| 8 | 若 `sig_ver == v3`：校验 assertion 的 SHA-256 与签名域一致 | 拒绝 |
| 9 | 若有 App Attest：验证 Apple attestation 链 + assertion 的 `clientDataHash` | 拒绝或降权 |
| 10 | 若启用字段映射：按 `field_mapping_version` 还原字段后再解析 | 拒绝 |
| 11 | 入库、聚合、图计算、策略决策 | — |

> **任一步失败即整体拒绝**，不得“降级取部分字段”。

### 9.2 服务端必须忽略的字段

- payload 内 `sr`（`ServerSignals`）：端侧上报的 IP/ASN/机房信息一律不可信，服务端必须以自己观测到的网络信息为准。
- `trust_level`：仅作为**降权提示**，不可作为放行依据。
- `binding_mode` / `binding_digest` / `output_path_integrity`：观测与告警用，不参与信任判定。

### 9.3 密钥与轮换

| 项 | 规格 |
|----|------|
| 密钥形态 | 字符串基密钥（UTF-8），v2h 下经 HKDF 派生 |
| 轮换 | `key_id` 标识；`TrustChainManager.currentKeyRotationPolicy()` 存在时自动切换 |
| 未知 keyId | 拒绝（客户端侧 `unknownKeyId`） |
| 密钥下线 | 服务端保留至少一个 nonce 窗口（300s）+ 时钟漂移（300s）的重叠期 |

| `ca` | category（`jailbreak` / `anti_tamper` / `integrity` / `network` / `behavior` / `device` / `server` / `system`） |
| `s` | 数值分 |
| `ev` | evidence（string→string） |
| `st` | 状态（hard/soft/tampered/serverRequired/unavailable） |
| `l` | 风险层（1/2/3/4） |
| `wh` | weightHint |

### 10.3 标识与版本策略

| 项 | 规则 |
|----|------|
| `reportID` | 每次 evaluate 新建，不复用 |
| `nonce` | 每次信封新建，进程内 300s 去重 |
| `sdkVersion` | `Version.current` = `9.0.0` |
| `signalsDigestVersion` | 当前 `v2a` |
| 契约版本 | `contract_version = 1`，破坏性变更需升 2 |

## 11. 降级与失败矩阵

### 11.1 检测能力降级

| 条件 | 行为 | 可观测信号 |
|------|------|------------|
| AppStoreSafe 档 | 跳过 attach 拒绝、异常处理、看门狗、反 dump、擦头 | 日志 `app_store_safe_profile` |
| watchdog 启动失败 | 取消心跳 | 日志 + `anti_debug_watchdog_*` 信号 |
| armor 未启动 | 不复查完整性、不擦头 | `armor_runtime_init_failed` |
| 完整性被污染 | 输出 `integrity_runtime_tampered`（85，tampered） | payload `sg` |
| 能力探针异常 | 追加 `capability` 信号 | payload `sg` |
| 高危信号消失 | `signal_suppression_detected`（80） | payload `sg` |
| 触摸/运动无样本 | 行为信号弱化，`bv` 为 nil | payload |

### 11.2 上报链路降级

| 条件 | 行为 | 调用方处理 |
|------|------|------------|
| armor 不可用 + `requireArmor=true` | throw `armorRuntimeUnavailable` | **不得改传明文**；降级为不带检测结果的普通请求，或阻断业务 |
| armor 污染 + `requireArmor=false` | v2d 普通 HMAC，`bindingMode=plain_hmac_fallback_v1` | 记录告警 |
| 字段映射强制但缺失 | throw `payloadFieldMappingRequired` | 等待配置下发 |
| 字段映射过期且强制 | throw `payloadFieldMappingExpired` | 同上 |
| App Attest 不支持 + 强制 | throw `hardwareTrustUnsupported` | 按业务风险决定是否继续 |
| App Attest 失败 + 非强制 | 降级信封 + `trustLevel=degraded` | 建议上报 `degraded` 比例监控 |
| 远程配置陈旧 | 追加 `remote_config_stale`（soft 0.3，weight 10） | 监控 |
| 远程配置回滚/同版本异内容 | 拒绝新配置，保留旧配置 | 日志 |
| kill switch | 强制 allow | 审计日志 |
| 自适应缓存 | 返回上一轮报告 | 注意报告 `ri` 与时间未更新 |

### 11.3 时钟异常

| 条件 | 行为 |
|------|------|
| 设备时间 < 2020-01-01 | `create()` 抛 `timestampOutOfRange` |
| 服务端时钟偏差 > 300s | 拒绝 `timestampOutOfRange` |
| nonce 超期 | 拒绝 `nonceExpired` |

## 14. 性能约束

> 以下均为 `PERFORMANCE_BENCHMARK.md` 中的**目标值**，真机大规模实测尚未完成，不构成 SLA。

| 阶段 | 旗舰目标 P50 | 低端目标 P50 |
|------|-------------|-------------|
| `start()` | ≤ 50 ms | ≤ 120 ms |
| `evaluate()` | ≤ 25 ms | ≤ 60 ms |
| 信号采集 | ≤ 10 ms | ≤ 30 ms |
| 决策引擎 | ≤ 5 ms | ≤ 15 ms |
| 信封构建 | ≤ 10 ms | ≤ 25 ms |
| Payload 大小 | ≤ 8 KB | ≤ 12 KB |

**调用约束**：

- `evaluate()` 是同步阻塞调用，不要在滚动、动画、主线程高频路径调用。
- 触摸/运动采样读取即清零，高频轮询会削弱行为特征。
- 建议在业务敏感节点调用：登录、注册、支付、账户变更、敏感操作。

## 16. 实现现状差异与风险

> 本节记录规格与当前代码的**真实差距**，接入方与维护者必须知晓。

| # | 现状 | 影响 | 建议 |
|---|------|------|------|
| R1 | `buildSecureReportEnvelope()` 在 Release 固定签发 `v2a`（legacy），并显式 `allowLegacySignatureVersions: true` | assertion 与 `trustLevel` **不在签名域**，可被替换/剥离 | 服务端必须拒绝 legacy；上报链路迁移到 `ReportEnvelope.create` 默认 v3 |
| R2 | 两条信封路径并存：高层 API 走 v2a，Collector 走 v3 | 接入方容易选错 | 文档首页明确推荐 Collector v3 路径 |
| R3 | `payload` 字段是明文 JSON | 机密性仅靠 TLS + 字段混淆 | 生产必须启用 TLS + `payloadFieldMapping` |
| R4 | `UploadPolicy` 是死代码（无调用方） | 上报时机完全由调用方控制 | 调用方需自行实现分级上报与退避 |
| R5 | `challengeBinding` 仅 DEBUG 允许本地合成 | Release 需服务端下发 `blindChallenge` | 生产必须由服务端驱动挑战 |
| R6 | 自适应缓存命中时返回旧报告对象 | `ri`、`ts` 不更新 | 缓存窗口内的业务判断需接受“同一报告复用” |
| R7 | 测试已从仓库移除，CI 只编译 + 契约检查 | 无回归保护 | 恢复上面 15.x 的用例为自动化测试 |
| R8 | Pass 13 禁用、Pass 1 原地改写不可用、Pass 12 真机启动未验证 | 加固能力有已知缺口 | 见 `Armor-Hardening-Audit.md` |
| R9 | 真机性能未实测 | 性能数字仅为目标 | 建立真机基线后再谈 SLA |

## 附录 A：一页速查

```swift
// 1. 启动
CPRiskKit.shared.start(config: .default)

// 2. 评估（业务节点调用）
let report = CPRiskKit.shared.evaluate(
    config: .default,
    scenario: .payment
)
print(report.score, report.isHighRisk, report.detectedMethods)

// 3. 构建信封（sessionToken / signingKey 来自服务端）
let envelope = try CPRiskKit.shared.buildSecureReportEnvelope(
    report: report,
    sessionToken: token,
    signingKey: key,
    keyId: "k1"
)

// 4. 传输
let body = try envelope.toGrpcRequestBytes(
    context: GrpcReportContext(appId: appId, deviceId: report.deviceID, scene: "payment")
)
// POST body

// 或者一行走 Collector（v3 + App Attest + enrollment）
let receipt = try await RiskDetectionService.shared.submitToCollector(
    report: report,
    collectorURL: url,
    bearerToken: bearer,
    appId: appId,
    sessionToken: token,
    signingKey: key,
    scene: "payment"
)
```

**必须记住的三件事**：

1. **不要在没有服务端 `sessionToken` / `signingKey` 的情况下上报**——信封会失去意义。
2. **不要在高危场景把 `requireArmor` / `requireAttestation` 设为 `false`** 来“让流程跑通”。
3. **同一信封只能重试，不能重建**——nonce 与挑战都是一次性的。
