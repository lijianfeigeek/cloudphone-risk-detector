# 源码中文注释规范

> 适用范围：`RiskDetectorApp/Sources/CloudPhoneRiskKit/**/*.swift` 与
> `RiskDetectorApp/Sources/CRiskCore/**/*.{c,h,inc}`
> 目标：让不了解风控 SDK 的工程师也能逐文件读懂“这段代码在做什么、为什么这么做”。

## 1. 粒度

| 位置 | 要求 |
|------|------|
| 文件头 | 2–5 行说明本文件职责、在管道中的位置、与其他模块的关系 |
| `// MARK:` | 按功能分组，标题用中文（保留 `MARK` 关键字） |
| 类型 / 协议 / 枚举 / 扩展 | `///` 文档注释：职责、线程模型、安全不变量 |
| 函数 / 方法 | `///` 文档注释：做什么、参数含义、返回值、失败/超时语义 |
| 存储属性 | 行尾或上方 `//` 说明用途、单位、取值范围 |
| 关键语句 | 上方 `//` 说明“为什么”，覆盖：安全校验、魔数/阈值、状态迁移、加解密步骤、超时与降级、平台兼容分支 |
| 普通赋值/循环 | 仅在意图不直观时注释；禁止“把代码翻译一遍”的废话注释 |

## 2. 语言与术语

- 使用简体中文。类型名、API 名、协议名、字段名保留英文原文。
- 统一术语：
  - Signal → 信号；Detector → 检测器；Provider → 提供者（信号源）
  - Verdict / LocalAssessment → 本地判决；Action → 处置动作
  - jailbreak → 越狱；anti-tampering → 反篡改；anti-bypass → 反绕过
  - cloud phone / vPhone → 云手机；emulator → 模拟器
  - envelope → 安全信封；attestation → 证明（App Attest 保留原名）
  - fail-closed → 失败即拒绝；degrade → 降级；kill switch → 总开关
- 保留既有英文专有名词的大小写（`RiskSignal`、`CPRiskKit`、`Frida`）。

## 3. 严格禁止

1. **不得修改任何代码 token**：标识符、字面量、运算符、空格缩进、import 顺序、代码行顺序一律不动，只允许插入注释行或行尾注释。
2. 不得在多行字符串 `"""..."""`、原始字符串 `#"... "#`、字符串插值 `\(...)` 内部插入注释。
3. 统一使用 `//` 与 `///`，**禁止 `/* */` 块注释**（避免嵌套与工具解析问题）。
4. 首行为 `// Generated by ...` 的生成文件跳过，不手改。
5. 大块字面量数据（S-box、混淆字符串表、字节码表）只在表头写一段说明，不逐行注释。
6. 不得为了注释而重排代码、拆分表达式或改写 API。
7. 不写废话注释，例如 `i += 1 // i 自增`、`return x // 返回 x`。

## 5. 验收

每个文件改完后，用 `RiskDetectorApp/Scripts/verify_comment_only.py` 校验：剥离注释后的代码必须与 git HEAD 完全一致（仅允许空行差异）。

```bash
# 校验指定文件
python3 -I RiskDetectorApp/Scripts/verify_comment_only.py "$PWD" <file1.swift> <file2.swift>

```

## 6. C 层（CRiskCore）补充规则

C 层注释的重点不是翻译代码，而是写清**调用契约**与**安全不变量**。

### 6.1 文件头

每个 `.c` / `.h` 开头 3–6 行：

- 文件职责、在检测/加密/加固链路中的位置
- 线程模型（单线程初始化、并发读取、原子变量语义）
- 平台/架构限制（simulator、arm64e、PAC/MTE、SVC 直调）
- 失败语义（fail-open / fail-closed）

### 6.2 导出函数文档模板

每个 public 函数至少覆盖以下 6 项，缺哪项就写“无”：

1. **做什么**：检测什么、操作什么
2. **参数与所有权**：是否允许 `NULL`、缓冲区大小、谁分配/释放
3. **返回值**：`0/-1`、正数含义；失败时 `error_out` 是否有效、是否写 `errno`
4. **线程安全**：可重入？只能在 init 前/后调用？能否并发？
5. **平台/架构**：模拟器、arm64e、PAC/MTE、SVC 是否可用
6. **失败语义**：调用方应如何处理（重试/降级/视为风险）

示例：

```c
/// 解析并调用 `dlopen`，失败时不写 errno。
/// - Parameters:
///   - path: UTF-8 路径；允许为 NULL（与 libc 语义一致）。
///   - mode: 同 dlopen(3) 的 RTLD_* 标志。
/// - Returns: 成功返回句柄；失败返回 NULL。
/// - Thread safety: 内部缓存由 `UnfairLock` 保护，可并发调用。
/// - Platform: 仅 arm64 真机走直调；模拟器回退 libc。
```

### 6.3 数据结构与常量

- `struct` 的每个字段：含义、单位、取值范围、所有权
- 位掩码逐位说明：谁置位、谁读取、能否重置
- 魔数/上限/阈值：为什么是这个值、改动会破坏什么
- `_Static_assert`：说明它锁定的 ABI 约束

### 6.4 宏与生成文件

1. **禁止在反斜杠续行的宏定义内部插入注释行**——注释会被拼进宏体，导致宏被截断。宏说明写在 `#define` 整体之前。
2. 函数式宏的每个参数含义写在宏上方的块注释里。
3. 首行含 `Generated by ...` 的 `.inc` 只补文件头（生成脚本、编译开关、默认是否启用），不手改正文。
4. C 文件统一使用 `//` 整行注释；文档块可用 `/* ... */`。不允许行尾注释（便于校验）。

### 6.5 验收

```bash
# 校验指定 C/H 文件（剥离注释后代码必须与 HEAD 一致）
python3 -I RiskDetectorApp/Scripts/verify_c_comments.py "$PWD" <file.c> <file.h>

# 额外编译校验（示例）
xcrun --sdk iphoneos clang -arch arm64e -miphoneos-version-min=14.0 \
  -fsyntax-only -isysroot "$(xcrun --sdk iphoneos --show-sdk-path)" <file.c>
```
